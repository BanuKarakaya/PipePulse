# PipePulse

Native macOS menu bar app for monitoring GitHub Actions and GitLab CI/CD pipelines, with deterministic demo data when no integration is enabled.

## Run

Open `Package.swift` in Xcode and run the `PipePulse` scheme. The app appears in the macOS menu bar. The first launch shows onboarding; the dashboard is then available from the PipePulse menu bar item.

From a full Xcode installation, the command-line equivalents are:

```sh
swift build
swift test
```

## Structure

- `Core/Models`: provider-independent repository and pipeline models.
- `Core/Networking`: `PipelineProvider` abstraction and URLSession transport boundary.
- `Core/Security`: Keychain token storage for future provider credentials.
- `Providers/Mock`: deterministic mock data used by the MVP.
- `Features`: dashboard, pipeline details, settings, and onboarding screens.
- `Components`: reusable status, summary, project, and empty-state views.

## GitHub Actions setup

Open Settings, enable GitHub Actions or GitLab CI/CD, enter the corresponding read-only API token, and add repositories as `owner/name` (one per line). Press Done to validate and save; tokens are stored in macOS Keychain. Both integrations can be enabled together. If all integrations are disabled, their fields stay hidden and the app uses mock data.

## Inspect a failed pipeline

Open a project, then click a failed run's **Inspect failure** row. PipePulse loads the failed jobs, shows failed step names (GitHub) or stage/failure reason (GitLab), and displays error-related log lines with surrounding context. Select another job to inspect its log. **Open full log** opens the job in the provider. **Retry loading** retries only the read request; it never reruns a pipeline.

- GitHub fine-grained tokens need **Actions: Read** for the repository.
- GitLab fine-grained tokens need **CI/CD → Pipeline: Read** to list jobs and **CI/CD → Job: Read** to read job logs. An existing pipeline-only token can monitor runs but cannot read logs. Classic GitLab tokens can use `read_api`.
- Jobs and logs load on demand, independently of background monitoring. Returning to the project cancels the view's outstanding requests. Project navigation stays stable across refreshes.
- At most 500 jobs are checked, and each log download is limited to its first 1 MB. The excerpt displays up to 80 lines / 16,000 characters. Limits are shown in the UI; use the provider link for complete data.
- Excerpts are selected locally, not generated by an AI model and not a guaranteed root-cause diagnosis. Logs are held in memory only. The active token and common token formats are redacted, but arbitrary secrets may remain: review before sharing.
- Expired logs, missing permissions, rate limits, and failures with no jobs have explicit states. Demo runs have no real logs. Retrying/canceling pipelines from PipePulse is not part of this read-only feature.

Permission references: [GitHub workflow jobs API](https://docs.github.com/en/rest/actions/workflow-jobs), [GitLab fine-grained permissions](https://docs.gitlab.com/auth/tokens/fine_grained_access_tokens_rest/).
